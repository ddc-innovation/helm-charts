No Ingress is rendered for this release, deliberately. This project publishes
exactly ONE DNS name and it belongs to Production, so a non-production release
owns no hostname - two releases claiming it makes Traefik serve the public URL
from whichever was applied last. Reach this release with:

  kubectl -n {{ include "dcipm.namespace" . }} port-forward svc/{{ include "dcipm.web.serviceName" . }} 8080:80
  # then browse http://localhost:8080   (nginx proxies /api/ to the `api` Service)

Verify after deploy
  kubectl -n {{ include "dcipm.namespace" . }} rollout status deploy/{{ include "dcipm.api.fullname" . }}
  kubectl -n {{ include "dcipm.namespace" . }} exec deploy/{{ include "dcipm.api.fullname" . }} -- wget -qO- http://localhost:{{ .Values.api.containerPort }}/health/ready

  Health must answer plain HTTP 200, never a 307. A 307 means
  Features__UseHttpsRedirection came out true: the pod CrashLoops, because the
  kubelet probes over plain HTTP and does not follow the redirect (R5). Check
  with `kubectl -n {{ include "dcipm.namespace" . }} describe configmap {{ include "dcipm.api.fullname" . }}-env`.
{{- if not .Values.api.trustedProxyCidrs }}

  WARNING: api.trustedProxyCidrs is empty. ASP.NET Core 8+ IGNORES
  X-Forwarded-For and X-Forwarded-Proto from peers that are not explicitly
  trusted, so the API will see every request as plain HTTP from an unknown
  proxy: CORS, redirects and audit source IPs are all wrong while every
  component reports itself healthy (R15). Normally the pod CIDR, 10.42.0.0/16.
